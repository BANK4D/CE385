## ข้อ 1 Callback 
Callback มันก็คือ ส่งฟังก์ชันไปให้ทำงานทีหลังนั่นแหละ แบบ error-first style เวลาฟังก์ชันจบมาก็โยก callback ตามมาถ้าเกิด error ส่งตัว error มาก่อน ถ้าสำเร็จก็ส่ง null 
แล้วตามด้วยข้อมูล 

## ข้อ 2 Promise 

Promiseคือ object ที่เก็บ "สัญญา" ว่าในอนาคตมีผลลัพธ์มาก็จะใช้ผลลัพนั้น สะดวกกว่า callbackไม่ต้องมีเฝ้าฟังแบบ callback ยุ่งๆ
ใช้ Promise.all() ผ่าน (`{ ...student }`) แล้ว chain .then() ทีละอัน ทุกขั้นต้อง return เพื่อส่งต่อให้ถัดไป .catch() จะจับ error ทั้งก้อนโค้ดได้ เเละปิดท้ายด้วย .finally()

## ข้อ 3 Async/Await
Async/await ก็คือการเขียน asynchronous code แต่ให้ดูเหมือน synchronous ใช้ `await` ก็จะหยุดรอให้ Promise settle ก่อน ถ้า reject มาเป็น error 

**Promise.all()** ใช้ตอนที่ "ต้อง ALL สำเร็จหมด" ถ้าตัวไหนล้มก็ร่วงหมด 

**Promise.allSettled()** ใช้ตอนที่ "รู้ผลทั้งหมดไม่ว่าเป็นยังไง" ล้มก็ไม่ป่วน เพราะต้องรายงาน เช่นการแจ้งเตือนผลสอบผ่านอีเมล + SMS + แอป — แม้ว่า SMS ล้ม ก็ยังอ่านข้อมูลอีเมลกับแอปได้ 

**Promise.race()** ใช้ตอนที่ "ตัวแรกที่จบ ไม่ว่าจะสำเร็จ ล้ม หรือหมดเวลา" ตัวอย่างเช่น mirror-A ตอบเร็วกว่า mirror-B ก็ใช้ A ไปเลย หรือค้นหาฐานข้อมูลแต่ timeout 800ms — ถ้านานเกินจริง ก็เลิกรอแล้วใช้แคชแทน

## ข้อ 4 Promise Combinator Selection
เลือก combinator ให้ตรงกับสถานการณ์

1. **Scenario 1** — หน้าแรก: โปรไฟล์ + ตารางเรียน + ประกาศ  
   → `Promise.all()` ต้องให้ทั้ง 3 ส่วนสำเร็จ ถ้าอันไหนพัง→ หน้าแรกเปิดไม่ได้

2. **Scenario 2** — แจ้งเตือนผลสอบ: อีเมล + SMS + แอป  
   → `Promise.allSettled()` ต้องรายงานผลครบทุกช่อง แม้บางช่องล้มก็ยังรันได้่ (ไม่ทำให้ promise ล้มทั้งหมด)

3. **Scenario 3** — Mirror server: mirror-A + mirror-B  
   → `Promise.race()` ใช้ข้อมูลจากเซิร์ฟเวอร์แรกที่สำเร็จ (ไม่รอตัวอื่น)

4. **Scenario 4** — ค้นหา: ฐานข้อมูล(1200ms) vs timeout(800ms)  
   → `Promise.race()` เกิน 800ms → ใช้แคชแทน
