# Workshop 3 — Asynchronous JavaScript

## ข้อ 1 Callback 

Callback มันก็คือ ส่งฟังก์ชันไปให้ทำงานทีหลังนั่นแหละ แบบ error-first style — เวลาฟังก์ชันจบมา ก็โยก callback ตามมา ถ้าเกิด error ส่งตัว error มาก่อน ถ้าสำเร็จก็ส่ง null แล้วตามด้วยข้อมูล พอได้แบบนี้

ข้อมุ่น (ที่ต้องจำ) คือ "ข้อมูลที่ได้มาจากไกลๆ" (setTimeout 300ms ตัวอย่าง) ต้องคืนแบบ clone ด้วย ห้ามส่งอ้างอิงเลย เพราะถ้าข้อมูลต้นฉบับเปลี่ยน ผลลัพธ์ที่ได้ก็เปลี่ยนตามไปด้วย น่ารำคาญมากครับ

## ข้อ 2 Promise 

Promise มันคือ — ก็ object ที่เก็บ "สัญญา" ว่าในอนาคตมีผลมา สะดวกกว่า callback ตรงที่อ่านได้เหมือนโค้ด sequential ทั่วไป ไม่ต้องมีเฝ้าฟังแบบ callback ยุ่งๆ

ใช้ Promise.all() ก็ resolve ด้วยสำเนา object ผ่าน spread operator (`{ ...student }`) แล้ว chain .then() ทีละอัน — ทุกขั้นต้อง return เพื่อส่งต่อให้ถัดไป .catch() จะจับ error ทั้งกองได้ ปิดท้ายด้วย .finally() ที่จะรัน ไม่ว่าจะเป็นยังไง

โอเค promisify() น่าสนใจอยู่ — แปลง callback-style ฟังก์ชันให้เป็น Promise ได้เลย ทำให้อ่านหลวมๆ หน่อย


## ข้อ 3 Async/Await
Async/await ก็คือ — เขียน asynchronous code แต่ให้ดูเหมือน synchronous นั่นแหละ ใช้ `await` ก็จะหยุดรอให้ Promise settle ก่อน ถ้า reject มาเป็น error ที่ try-catch จับได้ไง ไม่ต้องใช้ .catch() เยอะตัวอีก

สำคัญตรงนี้ — ถ้าลืม `await` ก่อน Promise.all() มันจะโยก Promise object ให้ มันไม่ได้โยกผลลัพธ์ขึ้นมา แล้ว code หลังจากนั้น (เช่น .forEach) จะจับ object มาทำ พัง ห้อม วิธีแก้ก็ใจเย็นๆ จำ await ให้ได้

reportSequential() มันทีละตัวเลย ใช้เวลา ~900ms (3 ตัว × 300ms) แต่ reportParallel() เอา Promise.all() มา ทำพร้อมกันในเวลา ~300ms — เร็วขึ้นหลายเท่า เพราะ ไม่ต้องรอทีละคนหรอก

## ข้อ 4 Combinators
นี่เป็นข้อสุดท้าย และสำคัญมากครับ — ต้องรู้ว่า Promise combinator ไหนใช้เมื่อไหร่ เลือกผิด ก็พัง

**Promise.all()** ใช้ตอนที่ "ต้อง ALL สำเร็จหมด" ถ้าตัวไหนล้มก็ร่วงหมด ลองนึกเหมือนกับหน้าแรกของเว็บต้องโปรไฟล์ + ตารางเรียน + ประกาศ ครบเด้อก็เปิดได้ ไม่งั้น error

**Promise.allSettled()** ใช้ตอนที่ "รู้ผลทั้งหมดไม่ว่าเป็นยังไง" ล้มก็ไม่ป่วน เพราะต้องรายงาน เช่นการแจ้งเตือนผลสอบผ่านอีเมล + SMS + แอป — แม้ว่า SMS ล้ม ก็ยังอ่านข้อมูลอีเมลกับแอปได้ นี่แหละจุดต่างกับ Promise.all()

**Promise.race()** ใช้ตอนที่ "ตัวแรกที่จบ ไม่ว่าจะสำเร็จ ล้ม หรือหมดเวลา" ตัวอย่างเช่น mirror-A ตอบเร็วกว่า mirror-B ก็ใช้ A ไปเลย หรือค้นหาฐานข้อมูลแต่ timeout 800ms — ถ้านานเกินจริง ก็เลิกรอแล้วใช้แคชแทน

ยากตรงที่ต้องเขียน timeoutPromise() เอง — ให้ reject เมื่อหมดเวลา แล้ว race กับการค้นหาจริงๆ ใครมาก่อน ใช้คนนั้น

## สรุปรวม
Callback → Promise → Async/Await — เป็นเรื่องวิวัฒนาของวิธีเขียน async code ทีละ "ตั้น" ที่ดีขึ้นไปเรื่อยๆ ถ้าจับได้ทั้ง 3 แบบแล้ว ข้อที่ 4 มันก็คือ เลือกใช้เครื่องมือให้เหมาะกับงาน เลยต้องจำ pattern ของ combinator แต่ละตัว ให้เป็นลูกคิด
